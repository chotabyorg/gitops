# WhatsApp Gateway Prod Secret Preparation

This prod overlay is intentionally still excluded from ArgoCD auto-discovery in
`platform/argocd/prod.yaml`:

```yaml
- path: "services/whatsapp-gateway-service/prod"
  exclude: true
```

Do not remove that exclude entry until secrets, image readiness, control-plane
support, and the rollout window are confirmed.

## Required Secret

The deployment reads environment variables from this Kubernetes Secret:

```text
name: whatsapp-gateway-secret
namespace: prod
```

The Secret must contain exactly these keys:

| Key | Source | Notes |
|---|---|---|
| `INTERNAL_API_TOKEN` | Existing prod control-plane internal token | Must match the `control-plane-service` value used for `/v1/internal/*` authentication. |
| `WHATSAPP_APP_SECRET` | Meta App settings | Used to verify `X-Hub-Signature-256` on WhatsApp webhook POST requests. |
| `WHATSAPP_WEBHOOK_VERIFY_TOKEN` | Meta webhook callback setup | Must match the verify token configured for the production WhatsApp webhook. |

Do not commit a raw Kubernetes `Secret` with real values. Commit only:

- `secrets.yaml.template` with placeholders.
- `sealed-secrets.yaml` generated by `kubeseal`.

The current `sealed-secrets.yaml` is not production-ready while it contains
`encryptedData: {}`.

## Placeholder Raw Secret

Use this only as a local template. Replace placeholders outside Git and do not
commit the generated raw file.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: whatsapp-gateway-secret
  namespace: prod
type: Opaque
stringData:
  INTERNAL_API_TOKEN: "<shared-prod-internal-token>"
  WHATSAPP_APP_SECRET: "<meta-app-secret>"
  WHATSAPP_WEBHOOK_VERIFY_TOKEN: "<meta-webhook-verify-token>"
```

## Generate SealedSecret

From the GitOps repo root:

```bash
cat > /tmp/whatsapp-gateway-secret.yaml <<'YAML'
apiVersion: v1
kind: Secret
metadata:
  name: whatsapp-gateway-secret
  namespace: prod
type: Opaque
stringData:
  INTERNAL_API_TOKEN: "<shared-prod-internal-token>"
  WHATSAPP_APP_SECRET: "<meta-app-secret>"
  WHATSAPP_WEBHOOK_VERIFY_TOKEN: "<meta-webhook-verify-token>"
YAML

kubeseal \
  --format yaml \
  < /tmp/whatsapp-gateway-secret.yaml \
  > services/whatsapp-gateway-service/prod/sealed-secrets.yaml

rm /tmp/whatsapp-gateway-secret.yaml
```

The repository README uses the basic `kubeseal --format yaml` pattern. If the
cluster requires explicit controller flags, DevOps should use the production
controller name and namespace, for example:

```bash
kubeseal \
  --format yaml \
  --controller-name "<sealed-secrets-controller-name>" \
  --controller-namespace "<sealed-secrets-controller-namespace>" \
  < /tmp/whatsapp-gateway-secret.yaml \
  > services/whatsapp-gateway-service/prod/sealed-secrets.yaml
```

After sealing, verify that `sealed-secrets.yaml` has non-empty `encryptedData`
entries for:

- `INTERNAL_API_TOKEN`
- `WHATSAPP_APP_SECRET`
- `WHATSAPP_WEBHOOK_VERIFY_TOKEN`

Do not paste or print real values in logs, PR comments, or chat.

## Render Check

After generating the sealed secret, render the overlay:

```bash
kubectl kustomize services/whatsapp-gateway-service/prod >/tmp/whatsapp-prod-render.yaml
grep -n "whatsapp-gateway-secret" /tmp/whatsapp-prod-render.yaml
grep -n "encryptedData" /tmp/whatsapp-prod-render.yaml
```

Do not inspect or share decrypted secret values.
